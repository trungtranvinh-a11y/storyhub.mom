SPEC MỚI
Tên tạm thời

Text Story Tracking & Analysis Workspace

1. Định vị sản phẩm mới

Đây là một web app giúp người dùng:

import truyện chữ từ file
tự động tách chapter ở mức cơ bản
trích xuất metadata sơ bộ
quản lý characters / chapters / events / plot threads
hiển thị dashboard phân tích truyện
cho phép người dùng sửa lại metadata nếu hệ thống detect chưa chuẩn

Sản phẩm này không còn là AI writing workspace.
Sản phẩm mới là:

Một workspace để theo dõi, phân tích và quản lý dữ liệu có cấu trúc của truyện chữ sau khi import file.

2. Vì sao đổi hướng này hợp với code cũ

Spec cũ của bạn vốn đã có các lõi sau:

Project
Character
Chapter
PlotThread
Event / Timeline
Dashboard
Auth
App shell
Prisma + service layer + REST endpoints

Những phần đó vẫn dùng được gần như nguyên xi nếu ta đổi ngữ nghĩa từ:

“người dùng tự viết truyện”

thành:

“người dùng import truyện chữ để phân tích và tracking”

Tức là bạn không cần đập bỏ toàn bộ, mà chỉ cần pivot domain.

3. Tư duy sản phẩm mới
Trước đây
user tạo story project
user viết chapter
AI hỗ trợ viết tiếp / rewrite / summarize / suggest next
Bây giờ
user tạo analysis project
user import file truyện chữ
hệ thống parse file
hệ thống chia chapter / lưu raw text
hệ thống detect character candidates / event candidates / metadata draft
user review và chỉnh sửa
dashboard hiển thị dữ liệu đã phân tích
4. Mục tiêu sản phẩm mới
4.1. Mục tiêu chính
Giúp người dùng import một bộ truyện chữ và biến nó thành dữ liệu có cấu trúc
Giúp người dùng theo dõi nhân vật, chapter, timeline và plot threads
Giúp việc đọc / quản lý / phân tích truyện dài trở nên trực quan hơn
Không phụ thuộc GPT API để app vẫn usable
4.2. Mục tiêu MVP
import được file truyện chữ
parse được text
chia chapter ở mức cơ bản
tạo được character candidates
tạo được summary / event draft theo rule hoặc metadata import
hiển thị dashboard
cho phép sửa dữ liệu thủ công

7. Chức năng chính của MVP mới
7.1. Tạo project

User tạo project mới để chứa một truyện hoặc một nguồn truyện.

7.2. Import file

User upload:

txt
docx
epub
pdf có text selectable
7.3. Parse nội dung

Hệ thống:

lấy text ra
normalize text
lưu raw text và normalized text
ghi ImportJob status
7.4. Tách chapter

Dùng heuristic để detect:

“Chương 1”
“Chapter 1”
“Hồi 1”
pattern heading
hoặc fallback chia section nếu không rõ
7.5. Detect character candidates

Hệ thống tạo danh sách tên ứng viên dựa trên:

proper noun candidates
tần suất xuất hiện
chapter đầu xuất hiện
số chapter có mặt
7.6. Tạo metadata draft

Hệ thống tạo:

chapter summaries sơ bộ
event draft sơ bộ
plot thread draft optional sau MVP nhẹ
7.7. Manual review

User sửa lại:

chapter title
summary
character names
gộp alias
event description
7.8. Dashboard

Dashboard hiển thị:

tổng số chapter
tổng số character
số event
số import jobs
chapter gần đây
nhân vật xuất hiện nhiều nhất
file nào chưa review
8. File import pipeline

Đây là chỗ quan trọng nhất của tactic mới.

Bước 1: Upload

User upload file truyện.

Bước 2: Parse

System đọc file và chuyển sang text.

Bước 3: Normalize

Làm sạch:

khoảng trắng
xuống dòng
ký tự rác
tiêu đề lặp
encoding bất thường
Bước 4: Chapter split

System cố gắng tìm chapter boundaries.

Bước 5: Candidate extraction

System trích xuất:

possible character names
chapter summaries draft
event draft
Bước 6: Persist

Lưu:

SourceDocument
Chapters
Character candidates
Events draft
ImportJob logs
Bước 7: Review

User chỉnh lại metadata đã detect.

12. MVP acceptance criteria mới

Một user mới phải làm được các việc sau:

tạo project
upload file truyện chữ
hệ thống parse được text
hệ thống tạo chapter records cơ bản
hệ thống detect được character candidates sơ bộ
user sửa lại chapter / character / event metadata
dashboard hiển thị dữ liệu tổng quan

Nếu làm được trọn flow này thì MVP mới đạt.

13. Rủi ro kỹ thuật cần chốt sớm
13.1. Định dạng file

TXT dễ nhất.
DOCX/EPUB/PDF-text nên hỗ trợ sau hoặc hỗ trợ nhưng tách parser riêng.

13.2. Chia chapter không chuẩn

Không phải truyện nào cũng có heading rõ.
Cần có fallback và manual review.

13.3. Detect tên nhân vật sai

Phải thiết kế UI review để sửa:

merge alias
xóa false positives
đổi role thủ công
13.4. Event extraction quá “ảo”

Đừng hứa tự hiểu plot quá sâu ở MVP.
Chỉ nên làm event draft nhẹ hoặc cho user tạo event thủ công.
